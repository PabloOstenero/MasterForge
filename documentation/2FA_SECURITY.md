# Two-Factor Authentication (2FA) Security Architecture

MasterForge implements a robust Two-Factor Authentication system based on the **TOTP (Time-based One-Time Password)** standard, specifically following **RFC 6238**.

## Overview

2FA adds an extra layer of security by requiring not only a password but also a temporary 6-digit code generated by an authenticator app (like Google Authenticator, Authy, or Microsoft Authenticator).

## Technical Implementation

### Backend (Kotlin / Spring Boot)
- **Library**: `dev.samstevens.totp:totp` for core HMAC-SHA1 calculations.
- **Protocol**: TOTP (Time-based One-Time Password).
- **Time Synchronization**: The server is forced to **UTC** to ensure global compatibility.
- **Verification Window**: A +/- 60-second window is allowed to account for minor clock drift between the client device and the server.
- **Persistence**: 
    - Secrets are stored as Base32 strings in the `users` table.
    - Recovery codes are stored in an encrypted/secure format using `@ElementCollection`.

### Frontend (Angular / Ionic)
- **QR Generation**: Uses the `qrcode` library to generate scannable images from the standard `otpauth://` URI.
- **Challenge Flow**: A dedicated interceptor modal (`MfaModalComponent`) handles the secondary authentication step during login.
- **State Sync**: The application uses the `currentUser` state to dynamically show/hide 2FA configuration options.

## Recovery System

To prevent account lockout in case a device is lost, MasterForge generates **10 unique Recovery Codes** (8 characters each) during activation.
- **One-time use**: Each recovery code is invalidated immediately after a successful use.
- **Export options**: Users can copy codes to the clipboard or download them as a `.txt` file.

## Security Considerations
- **UTC Enforcement**: All time-based calculations are performed in UTC to prevent timezone-related mismatches.
- **Manual Verification**: The implementation uses a robust manual check across multiple time buckets to ensure reliability without sacrificing security.
- **Secret Protection**: Secrets are never exposed to the frontend after the initial setup phase.

## User Workflow
1. **Setup**: User requests 2FA setup -> Server generates secret -> User scans QR.
2. **Activation**: User enters a 6-digit code to verify sync -> Server saves secret and generates recovery codes.
3. **Login**: Password verification -> MFA Token generation -> 2FA Code/Recovery verification -> Final JWT generation.
4. **Disabling**: Authenticated user can disable 2FA at any time, which wipes the secret and recovery codes from the database.
